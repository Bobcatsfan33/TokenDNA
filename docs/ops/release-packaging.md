# Release Packaging

TokenDNA ships as a local appliance bundle plus the Python SDK. The goal is for a customer to deploy the control plane inside their own network, next to their identity systems and AI agent runtimes.

The former `collector/` and `platform/` packages were removed during the v3
simplification. They are preserved in git history, but are not built, tested,
supported, or included in the current release bundle.

## Artifacts

Each enterprise release should include:

- Signed control-plane container image.
- `docker-compose.yml` and `docker-compose.production.yml` for local appliance deployment.
- TokenDNA SDK wheel.
- SBOM and provenance metadata.
- Release manifest generated by `scripts/build_release_bundle.py`.
- Local appliance and backup runbooks.

## Build Manifest

Generate the operator manifest:

```bash
python scripts/build_release_bundle.py --image-tag tokendna/control-plane:<version>
```

The default output is:

```text
dist/release-bundle/tokendna-release-manifest.json
```

The manifest records the product version, git SHA, deployment model, package paths, runbook hashes, required gates, and SBOM pointer.

## Required Release Gates

Before signing a release, run:

```bash
ruff check .
pip-audit -r requirements.txt --progress-spinner off
python -m pytest -q --import-mode=importlib tests
python scripts/generate_oscal.py
python scripts/stig_evidence.py
python scripts/collect_ato_evidence.py --fail-on-missing
python scripts/build_release_bundle.py --image-tag tokendna/control-plane:<version>
python scripts/ci/verify_enterprise_readiness.py --require-approved
docker compose -f docker-compose.yml -f docker-compose.production.yml run --rm tokendna-deployment-gate
```

The Docker gate verifies production preflight, applies TokenDNA storage migrations, and runs the live Postgres smoke path.
The readiness verifier blocks production promotion while any required external
assessment, operations, governance, compliance, or pilot gate is open.

## Customer Deployment Model

TokenDNA is not packaged as a hosted service. A pip install is appropriate for the SDK, but the control plane itself should run as a signed appliance image with Postgres, Redis, and ClickHouse colocated or connected through customer-owned infrastructure. Customer collectors and integration services use the documented SDK and control-plane APIs.

This keeps identity telemetry, audit state, agent workflow evidence, and enforcement policy inside the customer boundary.
